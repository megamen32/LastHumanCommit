# Behavioral acceptance scenarios for live integration

These scenarios are a test plan, NOT a report that live agents ran them. Static
validation and offline graph tests cannot prove model behavior or adapter support.

| Scenario | Expected observable behavior |
| --- | --- |
| Ambiguous substantial feature | Strong Lead decides/decomposes; no routine human plan-selection wait; independent review and real-use Tester follow |
| Independent frontend/backend lanes | Shared contract first; compatible lanes execute concurrently; joined product checked |
| Two workers writing a shared file | Re-scope, designate owner or dependency before parallel mutation |
| Difficult architecture | Strong decision model/Adviser or council starts directly; no mandatory cheap-model sacrifice |
| Repeated cheap-model failure | Diagnose cause and change method/decomposition/model; record actual outcome |
| Very expensive but useful testing | Overseer preserves justified testing rather than enforcing a cheap-token quota |
| Missing actual model selection | Report attestation limitation; do not claim requested alias ran |
| Long task loses direction | Fresh Overseer uses original objective and evidence, prescribes a concrete correction |
| Full feature | One fresh Tester really operates the changed surface; code/tests alone cannot pass |
| Standalone focus-group request | Different goal-driven Testers use isolated data/sessions without code; fix and fresh retest |
| Broken browser tool | BLOCKED_REAL_SURFACE/tool failure distinguished from a product defect |
| Council synthesis introduces a flaw | Independent review catches flaw in the synthesis despite good initial proposals |
| Successful local workflow improvement | Saved method is compared, discoverable and later reused on a relevant task |
| No useful retrospective signal | No empty journal ceremony |
| Existing project instructions and dirty edits | Preserved; changes are merged, not a wholesale tree replacement |

Run through an attested harness on isolated test artifacts. Capture actual model
IDs, commands/events, changed revision, tool evidence, accepted outcome and limits.
Record completed runs and their limitations in the active task. This plan itself
makes no claim that a model or browser run has happened.
