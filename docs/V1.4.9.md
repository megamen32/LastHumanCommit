# LHC 1.4.9 — native milestone acceptance debt

Before: a normal substantial UI task could finish with “UI done, no user
testing”; native Stop checked only hourly direction and 120-minute learning.
Now the canonical entry retains pending user acceptance in the same per-session
state as the original task and clocks. No command registration is necessary.
An existing session bootstraps on a supported tool/context boundary. Later human
UI assignments are recognized; compaction/restart preserve the debt and goal.

Intent comes from human task context and actual Git surface changes, including
HTML rendered inside server JS/Python/etc. Test fixtures and arbitrary tool
output do not create UI milestones. Narrow fixes, questions, read-only reviews
and testers do not need focus groups. Three hours remains the scale of a major
outcome, never a timer or a mandatory group for every CSS edit.

Codex's normal Stop requests concrete missing acceptance once with
`decision=block`; the continuation bound survives compaction and turn changes.
Interrupt, permission wait, tool failure and read-only tester roles suppress
automatic finish continuation. A blocked final explanation can stop honestly
with acceptance incomplete. No agent, tool, daemon, permission bypass, login or
autonomous scheduler is created. Existing Herder creation and model routing stay
in place. The hourly/120m checks and delivery/anti-SHA contracts are retained.
The exact generated Stop reason is remembered as native control when Codex
submits it as a user prompt; it cannot replace the human goal or surface binding.
A successful approved tool releases permission wait without releasing a manual
Interrupt/SessionEnd. Confirmed acceptance stays valid for the same surface even
if an archive/API later becomes unavailable; actual UI changes reopen the debt.

OpenCode V2 shares the canonical entry and state. It has no native Stop veto:
pending acceptance is injected at supported model/context and compaction
boundaries; terminal success alone cannot cause another model turn. Interrupted
and failed executions retain their own event semantics. An idle result is not
proof that acceptance succeeded. References: [OpenCode runtime hooks](https://dev.opencode.ai/v2/docs/build/plugins/),
[Codex native Stop input](https://github.com/openai/codex/blob/main/codex-rs/hooks/schema/generated/stop.command.input.schema.json).

## Evidence and limits

The gate consumes the existing Herder raw transcript/manifest exports. It records
the exact `Lineage manifest` returned by a native tool result: Herder's archive
belongs to its MCP-process workspace and may be outside the product CWD. No new
export option, manual move, summary receipt or signature is required. Existing
local exports are also discoverable. Task/surface references in current context
are automatic correlation; a literal original goal in the tester assignment
also works. URLs can come from the task, existing `LOCAL_RUN.md` or the tester's
actual surface assignment; the first human prompt need not contain a URL.

Acceptance needs at least two distinct fresh independent native sessions, varied
personas, actual browser navigation + interaction + an observed result after it,
and complete raw positive/negative feedback naming the goal, attempted steps and
observed outcome. Normal browser tool calls and separate browser CLI calls with
`--session NAME`, including managed SSH calls, are correlated within each child.
PASS alone, open-only, login-only, technical tests, self-attestation, repeated
tester/persona, stale/wrong-task evidence and explicit partial/not-tested reports
cannot accept the milestone. Outcomes are pending, changes-required, blocked or
accepted; old failures and raw feedback remain visible. A changed UI invalidates
old acceptance; a fresh successful retest can resolve older blocked attempts.

Codex evidence must match its native source under the active Codex sessions root,
not an arbitrary writable report file. OpenCode's partial message export alone
is insufficient: bounded read-only GETs against that same existing local native
API verify the session creation time/identity and exported message contents.
No credentials are retrieved. Unavailable/protected/remote APIs or unknown raw
formats remain unaccepted. Work is bounded to 16 exports, 8 MiB/source and a
two-second feedback read window; no background retries are scheduled.

This is a mechanical evidence floor, not a semantic UX grader or a cryptographic
boundary against an actor able to modify native session storage. It cannot prove
that every arbitrary business subgoal was exercised just because the report
claims it. Lead must read the original feedback, assess actual scenario coverage,
repair actionable findings and make honest acceptance claims. No fixed report
schema or new reviewer of receipts substitutes for that responsibility. Intent
and UI detection are bounded source/task heuristics; unsupported surfaces stay
subject to the router's full acceptance duty.

Validation here proves source/package/native hook behavior on isolated fixtures.
Installed-runtime fresh UI acceptance and real independent browser attempts are
owned by the coordinator and are not claimed by this implementation.
