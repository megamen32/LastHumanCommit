# LHC 1.4.4 — native OpenCode 2 integration

The 1.4.3 business/TDD/design/hourly/learning/milestone rules are unchanged.
OpenCode 2 rejects V1 hook dictionaries; `opencode/lhc-v2.ts` uses native
`setup`, session prompt/context/compaction hooks, tool hooks and event subscription.
It delegates timing and checks to the same Python guard, does not modify durable
user text, resolves the actual session directory and pauses on idle/permissions.
The event stream is cancelled on unload. Hook failure does not block the user.

`opencode-config.py --format v2` emits `plugins` and the v2 entrypoint. The native
V1 entrypoint remains separate. OpenChamber connected to the same OpenCode server
shares this installation; a second agent or duplicate checkpoint timer is unnecessary.

Primary API: https://opencode.ai/v2/docs/build/plugins/migrate-v1 ; verified schema
contracts from @opencode/plugin and @opencode/schema 2.0.31.

Real native smoke caught a lifecycle mismatch: v2 emits durable
`session.execution.succeeded/failed/interrupted`, not only legacy `session.idle`.
The adapter handles these terminal events and `session.compaction.ended`;
all three terminal outcomes have regression tests.
