# LHC 1.4: параллельная работа без лишнего процесса

## Изменение контракта

Основной вход автоматически принимает обычную инженерную задачу, включая неточную
голосовую формулировку. Нет обязательного выбора режима, первоначального Overseer,
трёхстрочной формы, почасового ритуала и автоматического самоулучшения по таймеру.
Архитектура, независимые review/Tester на существенном риске, проверка реального
сценария и бюджет результата сохранены. Старые рабочие инструменты времени и памяти
не удаляются, но сами по себе больше не назначают работу.

Сохраняется единая зелёная история. При параллельном писателе — отдельный worktree,
push/PR, merge при доступных правах и проверках. В конце fetch, интеграция свежего
main, повторная проверка общей версии. Свои готовые результаты публикуются до
ожидания коллег, чтобы не образовывались циклические зависимости. Последняя сессия
или интегратор завершает общий цикл, включая относящиеся к нему готовые изменения
коллег и вложенные репозитории. Чужой активный WIP не захватывается по таймеру.

Блокер откладывает конкретную операцию, пока выполняется доступная работа. Когда
остались зависимости от сессий, Herder `resume_after` сохраняет адресное ожидание.
Недоступный транспорт не выдаётся за разрешение менять чужие данные или за доставку.

Чат использует один атомарно публикуемый JSON на сообщение, отдельный курсор читателя
и один проектный корень для всех worktree. Системный адрес и SSH-межхостовый маршрут
описаны в `src/common/protocols/COORDINATION.md`.

## Почему меняются тесты старых формулировок

Старые проверки требовали дословно присутствия mandatory initial audit, three-line
minimal path и default PostToolUse timer. Они проверяли прежний контракт, который
пользователь изменил. В 1.4 эти проверки заменены контрактом автоматического входа,
соразмерных методов, PR/интеграции и продолжения независимой работы. Исполняемые
проверки старых инструментов, файловой безопасности, worktree, package parity и
адаптеров сохранены. Добавлены параллельный чат и проверка короткого native hook.

## Нейрослоп

Merriam-Webster определяет slop через низкое качество массового AI-контента.
Simon Willison отдельно подчёркивает навязанный, непросмотренный результат, а не
любое использование AI. Здесь это означает убрать текст и работу, которые не
меняют решения или результата, а не убрать нужную проверку или ясное объяснение.

Источники: https://www.merriam-webster.com/wordplay/word-of-the-year ;
https://simonwillison.net/2024/May/8/slop/ .

Исходники и автоматически собранный пакет — не доказательство обновления каждого
установленного harness. Установка и обычный запрос свежей сессии проверяются отдельно.
