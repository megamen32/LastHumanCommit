# Проверка сообщения после обновления LHC

2026-09-09: прежнее завершение было заявлено по недостаточной проверке.
Запуск Python-скрипта и обнаружение хуков не проверяли пользовательское сообщение.
Lead отвечает за соответствие доказательства заявлению; Tester проверяет сам
клиентский путь; Overseer отвергает завершение без этого результата.

Реальный Codex app-server, ephemeral session, штатные marketplace upgrade и
plugin add: сессия, открытая на 1.2.4, после установки 1.2.5 получила
UserPromptSubmit status=blocked, Python exit 2, отсутствующий файл кэша 1.2.4.
Тот же клиент сообщил turn/completed, но ответ агента отсутствовал: сам статус
завершения хода тоже не является доказательством прохождения сообщения.
Новая сессия на 1.2.5 ответила LHC_MESSAGE_OK; хуки SessionStart и
UserPromptSubmit завершились успешно.

Исправление в 1.2.5: ошибка наблюдателя времени завершает shell-команду кодом 0
с диагностикой, сохраняя возможность отправлять сообщения. Это не доказывает
работающий учёт времени при исчезновении исполняемого файла. Старые сессии,
запомнившие прежнюю команду без обработки ошибки, требуют перезапуска сессии.

Переход 1.2.5 → 1.2.6 проверен тем же реальным клиентом: ранее открытая сессия
и новая сессия обе получили LHC_MESSAGE_OK, SessionStart и UserPromptSubmit
имеют status=completed. Старая сессия использовала команду кэша 1.2.5, новая —
1.2.6. В новой сессии наблюдатель также выдал своё предупреждение об отсутствии
интервального учёта: выполнение расширения подтверждено отдельно от ответа.
При удалённом старом пакете fail-open сохраняет сообщения, но не восстанавливает
сам учёт времени; для этого требуется новая сессия на установленной версии.
Область проверки: локальный native Codex app-server; Desktop UI и другие
клиенты этим испытанием не подтверждаются.
