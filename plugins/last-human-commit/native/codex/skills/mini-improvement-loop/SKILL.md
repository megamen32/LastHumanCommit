# Finish a defect list

Use for a bounded repair list. A single obvious bug can be fixed directly; an unresolved architecture choice needs design work first.

Group findings by cause and ownership. Assign independent fixes in parallel where useful. Give each executor the symptom, affected paths, relevant invariants and the scenario that should pass.

Integrate the fixes and check the affected behavior. Review shared boundaries when the changes interact. Prioritize defects that block the requested result and regressions from the fixes; keep unrelated suggestions separate.

When a repair fails repeatedly, reconsider its cause with the existing evidence. Ask an Adviser only when another judgment is needed. Finish through the real client and the authorized delivery route. Keep useful commits and results so another session can continue the work.
