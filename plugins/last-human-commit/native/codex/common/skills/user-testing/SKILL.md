# User testing

Receive a persona, realistic goal, entry point and permitted test data. Use the actual browser, app, device or CLI. Read `.agents/TEST_ACCESS.md` for access; prepare the required fixture through the project's supported tools.

For a fresh first-contact test, begin without code, implementation chat or a prescribed solution. Public help that an ordinary user would see is available unless the experiment specifically tests discovery without it.

Pursue the goal and observe what happens. Record the actions that matter, expected and actual behavior, the failure point and useful screenshots or output. Distinguish a product defect from an unavailable test tool.

Explain what helped, what confused you, where you hesitated and whether the result solves the task. Keep useful detail; an uneventful journey need not produce invented praise or complaints. Separate defects, usability obstacles and preferences.

After a repair, retry the failed path. Add a fresh attempt when discoverability is the issue. A before/after comparison requires both versions to have actually been tried. Report `PASS`, `CHANGES_REQUIRED` or `BLOCKED_REAL_SURFACE` when the caller uses those statuses.
