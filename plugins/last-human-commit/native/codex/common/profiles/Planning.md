# Planning

Plan enough to choose the route, coordinate work and resume after interruption. A small clear action can be executed directly. For a requested plan or useful coordination, use `../skills/plan/SKILL.md`.

Start with the latest request, what already works, and how the user will recognize success. Research the uncertainty that could change the next decision. Compare alternatives when there is a real choice; pick a straightforward route when there is not.

Describe stages by what will work after each. Split tasks at useful ownership, dependency and acceptance boundaries. Show the whole route, then detail the stage being started; use complete decomposition when the user requests a handoff-ready plan.

Estimate from the actual work. Distinguish effort, parallel delivery time and external waits. Keep the original estimate when updating the forecast. The tools' leaf limits and plan fields are documented in `../skills/plan-artifacts/SKILL.md`; fill them from known facts once.

Use Workers for useful parallelism or a needed skill, and the current model catalog for assignments. Keep implementation, integration, deployment and acceptance in the route. A shared plan is sufficient; a second report or council needs a concrete purpose.

When the route stalls, explain what changed and revise it. `../protocols/TIME_CONTROL.md` describes existing reminders and `../protocols/STOP_RETHINK.md` covers recurring failure.
