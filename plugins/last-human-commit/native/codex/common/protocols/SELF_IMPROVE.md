# Improve the way the work is done

Use this when the user corrects the method, a failure repeats, an approach wastes substantial effort, or a useful technique could help later tasks. Existing time reminders can prompt this look. A routine successful task needs no retrospective.

Read the original goal, latest correction and recent actions. Find the cause of the wasted work and the instruction or tool that owns it. Prefer a concrete correction: remove a duplicate step, repair the tool or choose a better next action.

Try the changed method against the original problem and relevant contrasting cases. Save the useful result in its existing skill, tool or project note, with the evidence and conditions for reuse. A project-specific issue belongs in the project; a reusable LHC lesson belongs in LHC.

When there is no useful change, continue the task. A timer does not require inventing a lesson. A larger unrelated improvement goes into the backlog rather than delaying the requested result.

## Existing record mechanisms

The session guard can record the observation, correction and next route. Use it when that state is needed to continue the session; keep actual verification and later reuse distinct. New cards and compaction retain the original task clock.

Hermes uses its native memory/skill mechanism and `/learn` for storage. Other runtimes use their available memory or the project record described in `MEMORY.md`. Store the lesson once in the appropriate place and update it when evidence changes.

An Adviser can help when the cause remains unclear. Give it the relevant original request, facts and attempts. Boss already reads active work; a known repair does not need another supervisory session.
