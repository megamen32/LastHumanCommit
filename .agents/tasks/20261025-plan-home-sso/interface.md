# Контракт корневого каталога и существующего SSO

Сервер зеркала: `sso_enabled: true` в существующем JSON config. После успешного
`auth_request` nginx ПЕРЕЗАПИСЫВАЕТ `X-LHC-SSO-Verified` значением `1` при
проксировании `/` и `/dashboard/<key>/`. Источник принимает его только при
loopback TCP peer (`127.0.0.1` / `::1`). Внешний клиентский заголовок не передавать.
Не использовать forwarded IP для принятия решения. Без признака возвращается 401.

При SSO `/` и старый capability URL показывают один каталог. Без SSO `/`
возвращает 404, старый capability URL сохраняет прежнее поведение. Корень с SSO
не требует dashboard_key_file; при его наличии старый URL защищается тем же SSO.

Владелец hosting защищает ВСЕ браузерные маршруты: корень, capability, планы,
current, архивные ревизии, HTML и JSON. Proxy upstream доступен только loopback.
`/v1/snapshots`, `/v1/status` сохраняют Bearer: SSO cookie/заголовок их не
авторизует и отсутствие браузерной сессии не блокирует запись/синхронизацию.

Каталог содержит все снимки серверного зеркала, группирует по `snapshot.project`,
сортирует по времени исходного файла; не обещает полноту всего компьютера.
Автообновление каждые 12 секунд сохраняет поиск/фильтр. 401/403/redirect или
не-каталог при обновлении сохраняет старые данные и предлагает заново войти
через текущий корневой URL (nginx перенаправляет в существующий SSO).

Дополнение по инвентаризации: client config принимает `graph_sources` — список
абсолютных путей к существующим `plan.graph.json`. Наблюдатель читает графы,
не изменяя их и не создавая leaves. Явные пути нормализуются и дедуплицируются.
История/состояние сохраняются рядом в `.lhc-graph-publication-<path hash>`;
для sidecar нужны права записи в родительский каталог. Тот же observer и Bearer.
Невалидный/отсутствующий граф сохраняет последний хороший снимок и локальную
ошибку синхронизации. После восстановления ошибка очищается успешной синхронизацией.
