# Локальный план с автоматическим зеркалом

До: публикация зависит от вызова агента и синхронного транспорта. После: обычное сохранение plan.json или leaves/*.json само появляется по прежней постоянной ссылке; недоступность сервера не задерживает разработку.

Источник истины: локальные plan.json, leaves/*.json, .lhc-publication/revisions и observed.json. Сервер хранит восстанавливаемую проекцию. Режим fullcycle задан поручением Lead; это ограниченный исполнитель без координации чужих проектов.

План: 1) контракт и локальный durable snapshot/outbox (оценка 15 минут); 2) ingest, renderer и приватная панель (15 минут); 3) CLI/MCP/package и регрессии (15 минут); 4) stopped-server/recovery consumer и передача hosting для Mac/live (15 минут). Работа последовательно, один исполнитель, один слот. Активное время пока не измерено. Установку и настоящий Mac проверяет назначенный infrastructure Worker.

Рабочее решение: один stdlib CLI с watch/serve/register/status/once, локальная история и файловая очередь. Идеальная версия: native filesystem events и сложная очередь. Полезный минимум: polling hashes + debounce, один последний durable снимок на план, неизменяемые локальные ревизии, монотонные seq и явные конфликты владельцев. Нативные watcher зависимости и двусторонняя синхронизация отложены.

Приёмка: raw save без publish; malformed save сохраняет last-good; offline revise и перезапуск observer; prompt CLI/MCP при отказе сети; rebuild replica; stale/recent UI; сохранение URL/r001; настоящий Mac raw edit по hosting.md.
