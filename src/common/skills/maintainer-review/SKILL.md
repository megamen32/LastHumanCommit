# Maintainer review

Give a fresh reviewer the target repository, goal and diff. Read relevant contribution instructions, nearby code, tests and required CI checks before judging the change.

Report defects and convention mismatches with locations, examples and practical repairs. Cite a written rule when one applies. Describe inferred conventions as judgments, not invented project requirements. Separate preferences from issues that affect acceptance.

The author fixes substantive findings or explains why they do not apply. Recheck the affected delta. Use the repository's actual review and merge policy.
