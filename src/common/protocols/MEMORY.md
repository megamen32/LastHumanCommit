# Reusable knowledge

Save a finding when a later task is likely to need it: a production path, verified configuration, root cause, useful recovery procedure or a direct user decision. Keep the date, conditions and source reference.

Use the existing owner: shared `agentmemory` when appropriate, otherwise the harness's persistent memory or a project note. A project rule belongs in its instructions; an investigation belongs in `.agents/tasks/`. One canonical record is enough; link it from an index when that helps retrieval.

Search for the existing fact before adding a duplicate. Update stale guidance and keep assumptions distinct from verified observations. Secret values remain in the protected store; memory can hold their reference and purpose.

One-run logs, disposable scripts and facts already clear from current source usually need no separate memory entry. Saving a useful finding should not delay a working result.
